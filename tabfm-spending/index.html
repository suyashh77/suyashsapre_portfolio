Where does TabFM help with expense categorization?

TabFM averaged 87.2% accuracy, compared with 84.7% for a forest using the same compact features and 88.4% for a forest retaining the full text representation. Removing or misleading headers changed none of the 500 predictions or class probabilities.

Exploratory personal-ledger study · 2023-2026 · October 25, 2026 · Frozen official classifier, one ensemble member on CPU

SituationTaskAnalysisResult

An exploratory answer from four years of college spending, with controlled header and information ablations. October 25, 2026.

Situation

Hearing about Google's TimesFM 3.0 prompted a broader question about a possible "ChatGPT moment" for numerical prediction: how much useful task adaptation can a pretrained model perform without updating its weights for every dataset?

TimesFM-3 forecasts numerical sequences and supports related target series, past covariates, and known future inputs [1]. TabFM addresses table classification and regression. It is pretrained on synthetic tables generated from structural causal models, then uses labeled context rows to predict other rows with frozen weights [2]. This study applies that idea to expense categorization.

The data are a manually maintained college spending tracker. Its reconciled selection contains 2,499 expenses from 2023-2026 in nine personal categories. The records already contain some human editing. Source reconciliation retained 2,446 primary records, added 53 explicitly categorized records, and quarantined 28 unresolved view rows. Exact dates are unavailable for the 2023 academic-term records.

Task

Determine which conditions favor this released TabFM pipeline, which favor a fitted baseline, and whether the model uses semantic column names. A related question is whether names inside transaction descriptions supply meaning to the base classifier, or simply identify recurring values.

The practical aim is to choose how to use a foundation model based on the information and deployment setting available. The study evaluates one personal taxonomy. Conclusions about other domains remain hypotheses for further testing.

Analysis

Existing comparisons

The earlier reconciled study compared five pooled-year, category-stratified 80/20 splits, each with 1,999 context/training records and 500 test records. Every pipeline received the same rows. Full-text Random Forest and logistic regression used character TF-IDF features, plus signed log amount and month. TabFM used 16 training-fitted SVD components of those character features plus the numeric inputs. A matched-feature forest received exactly the compressed inputs supplied to TabFM.

Additional tests kept exact normalized descriptions on one side of a group split, varied context size from 128 to 1,536, reserved 2026, compared uniquely linked human-edited descriptions, and selected confidence gates on validation data. Vocabulary, IDF, imputation, scaling, and SVD were fitted on training/context rows only. The grouped split concerns normalized strings rather than verified merchant identities.

New header and information tests

Seven actual TabFM inference configurations reused the primary 1,999/500 partition. Column positions, numeric values, row order, labels, and classifier settings were fixed. The character-feature inputs were presented as a DataFrame with descriptive names, a NumPy array with no headers, and a DataFrame with deliberately irrelevant weather names. This isolates the use of header text while preserving the table.

The mixed numeric/categorical inputs were tested with descriptive headers and with integer column identifiers, which remove textual names while retaining column dtypes. A third version also replaced every distinct original description with a deterministic opaque identity token. Equality, frequency, and order of recurring descriptions were preserved. Those tokens went through the categorical encoder, never through the character-feature pipeline.

The official preprocessing outputs were checked before inference. Each header pair, and the original-versus-opaque categorical pair, produced identical numeric inputs for both context and test. A final configuration removed descriptions entirely and retained only amount and month with their training-fitted missing-value handling.

"No headers" therefore means no textual column names. The columns, data rows, and labeled context remain available. This experiment does not test reordered fields or incorrect types, and opaque IDs retain repeated-identity information.

This remains supervised in-context classification: the 1,999 context rows include their category labels. Header removal leaves that supervision intact. Category discovery from an entirely unlabeled ledger is a different experiment.

Implementation and scope

The official pinned classifier used frozen weights, float32, four CPU threads, one ensemble member, and no feature permutation or class shift. The executed checkpoint contains 1,639,444,298 parameters, whereas the paper abstract describes 400M. The precise released configuration is identified in the provenance records. It is a single-member CPU evaluation, not a reproduction of the paper's benchmark or the default 32-member ensemble.

This extension was specified after the earlier results were examined. It reuses an explored test set. Both studies are exploratory, with no untouched external confirmation. The new protocol is header_study_protocol.json, and all probabilities, predictions, and input-equality checks are retained.

All 500 predicted categories were unchanged in each controlled pair. The largest absolute probability difference across these pairs was 0. The model's numeric tensors are produced from values and types, so changing the names cannot teach it what a column means. The controlled result confirms the input path used by this released classifier. It does not establish robustness to missing fields or a corrupted schema.

Header invariance tests which inputs are used. It supplies no separate evidence that a foundation model is better than a fitted classifier. The outcome comparisons below address predictive usefulness.

Replacing transaction names with opaque IDs also preserves the categorical encoding. That condition achieved 78.0%. It can still exploit recurring identities and relationships with amount and month. In this partition, 340 of the 500 test descriptions occur exactly in the original training descriptions. Accuracy in the opaque-ID condition was 90.6% on that subset and 51.2% on the remaining strings. These subset figures are descriptive and depend on the chosen split.

Character-feature TabFM scored 86.2% without headers, while the numeric-only configuration scored 54.4%. The already tested forest using exactly those amount/month inputs scored 40.2% on the same 1,999/500 split. TabFM therefore exceeded that fixed numeric-only baseline by 14.2 percentage points in this case, while both remained weaker than their text-feature pipelines. This new TabFM numeric comparison has only one split, so its stability has not been established.

The numeric representation includes a month-missing indicator. In these files, missing month is associated with the 2023 academic-term recording format. The numeric-only result can therefore reflect recording conventions as well as amount and calendar relationships. It is not an amount-only experiment.

Training-fitted character features expose shared spelling patterns that categorical identity codes cannot express. The improvement with character features concerns representation, with the model weights held fixed. It does not demonstrate pretrained language understanding of descriptions.

TabFM was competitive in the pooled random task. It exceeded the matched-feature forest's mean by 2.56 percentage points, and its description-disjoint score was higher than that same compressed-feature comparator. Together with the primary-split numeric-only advantage, these are useful results when the supplied inputs are compact numeric features. A causal claim that pretraining alone created the gain would require further controls, including a suitable untrained or differently pretrained model.

The full-text forest averaged 88.4%, compared with 87.2% for TabFM. It also performed better on new description groups (77.0% versus 72.2%) and on the 2026 holdout at 1,536 context rows (73.8% versus 64.1%). For this expense task, it is the stronger reference pipeline. The comparison includes a representation difference, which is why the matched-feature results remain necessary.

Category performance also varied. Across the five random splits, TabFM's mean category F1 was 0.934 for Eating out and 0.935 for Groceries, compared with 0.621 for Football and 0.692 for Miscellaneous. A hypothesis is that some category boundaries require intent or context absent from the recorded fields. This study has no independent label adjudication to distinguish that explanation from label inconsistency or model error.

Frozen-weight inference also incurred computation. In the five earlier random cases, median model-stage time was 86.3 seconds for TabFM and 4.7 seconds for the full-text forest. These measurements cover context setup or model fitting and prediction after shared feature preparation; checkpoint loading is excluded. They concern this CPU implementation and hardware session, rather than a general latency benchmark. Avoiding weight training did not produce a speed advantage here.

The random and grouped scores answer different deployment questions. Random splits allow recurring descriptions to cross the partition and resemble filling gaps in the existing tracker. Holding out description groups is closer to encountering new strings. A future-year holdout additionally changes the period being predicted. The latter two expose weaknesses hidden by the random mean, although they also change the test population and cannot isolate a single cause of the drop.

A supported way to use the model

The evidence supports evaluating TabFM as a frozen predictor over carefully prepared features, alongside a fitted baseline, with a review path for uncertain records. It supplies useful predictions without optimizing its pretrained weights for this ledger. It still requires labeled context and locally fitted preprocessing.

In the earlier validation-gating case, 1,599 records supplied fitting context, 400 selected a threshold, and 500 remained the outer test. A threshold selected for 95% observed validation accuracy accepted 410 test records (82.0%) with 95.1% accuracy, leaving 90 for review. The accepted-record 95% Wilson interval was 92.6% to 96.8%. This is a measured operating point, not a certified future accuracy level.

The threshold selected for a 90% validation target yielded 88.9% accepted test accuracy at 95.2% coverage. Meeting a target in validation did not guarantee meeting it on test. Both operating points are reported so the successful 95% case is read alongside a target that did not carry over.

For this project, preserving useful description patterns and defining the intended holdout matter more than supplying descriptive headers. An LLM or a frozen text embedding could supply additional semantic features, but that benefit has not been measured here. Recorded human edits improved TabFM on a selected paired subset, and may already contain category knowledge. Any automatic text transformation needs a fresh, leakage-controlled evaluation.

For forecasting, the corresponding research design would use a forecasting model such as TimesFM, fix rolling forecast origins, give each comparator the same available history and future-known inputs, and evaluate interval width alongside coverage. That design follows the distinct forecasting task. The present classification experiments cannot establish that a time-series model will improve stock orders or sales forecasts.

Next research questions

The next confirmatory test should reserve newly collected transactions before changing the workflow, adjudicate ambiguous category labels, and verify merchant identities where possible. Repeat the numeric-only comparison across seeds before treating its observed advantage as stable. Compare the same text representation in TabFM and a fitted baseline, then add a frozen semantic embedding as a separate factor. A larger ensemble and the current CPU configuration would also need an explicit accuracy/cost comparison. The current data do not answer those extensions.

The defensible answer is conditional. TabFM handles tables without semantic headers and benefits from informative engineered features. On this ledger, its performance is competitive for familiar-record interpolation and stronger than one matched compressed-feature baseline. The full-text forest performs better overall, while unfamiliar descriptions and future periods remain difficult. Foundation-model usefulness is established by those conditions and comparisons, rather than by the foundation-model label alone.
